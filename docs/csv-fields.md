# cards.csv 字段说明

卡牌内容的唯一来源。改这里 → push → GitHub Actions 自动生成 `cards.json` 并同步页面。

---

## 一、总览

| # | CSV 列名 | JSON 字段名 | 类型 / 取值范围 | 必填 | 卡面显示在哪 |
|---|---|---|---|---|---|
| 1 | `version` | （作为 `versions` 的键） | 字符串，如 `v6` | ✅ | 不显示（决定版本下拉） |
| 2 | `deck` | `deck` | `chance` 或 `fate` | ✅ | 决定底色与标题（机会=粉紫 / 命运=米黄） |
| 3 | `seq` | ❌ 不进 JSON | 整数，从 1 开始 | 建议填 | 不显示，仅作人工核对 |
| 4 | `face` | `face` | `smile` 或 `frown` | 机会牌 ✅ / 命运牌留空 | 机会牌的表情图标 |
| 5 | `event` | `event` | 任意文本 | ✅ | 卡面正文第一行（事件描述） |
| 6 | `effect` | `effect` | 任意文本 | 机会牌 ✅ / 命运牌留空 | 机会牌第二行（效果） |
| 7 | `cond` | `cond` | 任意文本 | 命运牌 ✅ / 机会牌留空 | 命运牌「摇骰 · xxx」行 |
| 8 | `win` | `win` | 任意文本 | 命运牌 ✅ / 机会牌留空 | 命运牌「赢：xxx」（笑脸） |
| 9 | `lose` | `lose` | 任意文本 | 命运牌 ✅ / 机会牌留空 | 命运牌「输：xxx」（哭脸） |
| 10 | `rate` | `rate` | 如 `50%` | ❌ | 不显示，纯备注 |
| 11 | `use` | ❌ 不进 JSON | `1` 采用 / `0` 弃用 | ❌（留空 = `1`） | `0` 的牌不出现 |

> **空值不进 JSON**：转换时值为空的列会被整列省略，JSON 里不会出现空字符串字段。

## 二、两个花色的填法差异

页面靠 **`cond` 列有没有内容** 来区分渲染成哪种卡面，所以两种牌要填的列是互斥的。

### 机会牌（`deck = chance`）

填 `event` + `effect` + `face`，**`cond` / `win` / `lose` 必须留空**。

```csv
v6,chance,1,smile,你在瑞士的匿名账户被发现，你抢先举报同桌开曼账户的同行，瑞银发洗钱举报奖金,+2000，被举报者（最有钱的玩家）-2000,,,,,1
v6,chance,15,frown,你在拉斯维加斯出千被真正的赌场抓了现行,强制拍卖该处房子，拍卖所得上交赌场,,,,,1
```

- `face = smile` → 笑脸 + 粉紫底白字（奖励）
- `face = frown` → 哭脸 + 粉紫底白字（惩罚）
- 斜体提示：**机会牌一旦填了 `cond`，页面会把它当成命运牌来画**（出现摇骰/赢/输三行），属于填错。

### 命运牌（`deck = fate`）

填 `event` + `cond` + `win` + `lose`，**`effect` 填了也会被忽略**（命运牌不渲染这一行）。

```csv
v6,fate,1,,你在德州跟亡命牛仔玩「灵魂赌局」，背对背各走十六步才回头开枪,押大小（前八步/后八步）,抢先开枪：+3000,送进监狱 3 回合,50%,1
```

- 赢行固定用笑脸、输行固定用哭脸，`face` 列对命运牌无效，留空即可。

## 三、逐列说明

### `version`
版本代号。同一个 `version` 的所有行构成一个版本，页面顶部的**版本下拉**按 CSV 中首次出现的顺序列出。

新增版本（比如 v7）：直接在 CSV 末尾追加一批 `version=v7` 的行即可，不用新建文件。
想让下拉显示中文名，去 `tools/update.py` 顶部的 `VERSION_LABELS` 加一行；没配的话就显示版本代号本身。默认选中哪个版本由同一个文件里的 `DEFAULT_VERSION` 决定（当前是 `v6`）。
改完记得跑 `python3 tools/update.py`（或双击 `update.command`）。

### `deck`
- `chance` → 机会牌，粉紫底 `#B06F88`
- `fate` → 命运牌，米黄底 `#D9BA8E`

必须是这两个小写英文值之一，填错会导致校验失败、脚本不写文件。

### `seq`
牌的编号，**只用于人工核对，不参与渲染**。

页面上的卡号 `n-20` 是按「该花色在 CSV 中的出现顺序」自动生成的，跟 `seq` 列无关。所以别打乱行序，也别让 `seq` 和行序对不上，否则打印出来的编号和表里看到的编号不一致。

### `face`
仅机会牌有效：`smile`（奖励，笑脸）/ `frown`（惩罚，哭脸）。
命运牌留空 —— 它的表情由 `win` / `lose` 行固定死。

### `event`
卡面正文第一行。机会牌在这里写事件；命运牌写事件 + 判定缘由（为什么要摇骰）。

### `effect`
机会牌的效果文字，显示在 `event` 下方一行。
命运牌不要填，填了也不会显示。

### `cond` / `win` / `lose`
命运牌专用三件套，渲染成：

```
摇骰 · <cond>
😊 赢：<win>
😢 输：<lose>
```

机会牌必须留空，尤其 `cond` —— 有值就会被误判成命运牌。

### 金额的正号不用操心

`effect` / `win` / `lose` 里写 `+3000` 还是 `3000` 都行，**显示出来都是 `+3000`**。

原因是 Excel / Numbers 打开 CSV 会把 `+3000` 当数值，保存时正号被丢掉（负号 `-500` 和带文字的 `+2000，被举报者…` 不受影响，它们被判成文本）。所以脚本在读取时会自动补：只要一个格子**整个就是一个正整数**，就补上 `+`。

已经丢过正号的 CSV 不用手改，跑一次脚本页面就正常了。

### `rate`
命中率备注（如 `50%`、`43.75%`）。会原样进 JSON，但页面不读它，纯粹方便你核对零期望。

### `use`
- `1` 或不填 → 采用
- `0` → 弃用，这张牌不会进 JSON，页面上也消失

想临时拿掉某张牌试效果，把它改成 `0` 比删行安全，随时能加回来。

## 四、JSON 长什么样

`cards.json` 的结构（由脚本生成，不用手改）：

```json
{
  "default": "v6",
  "order": ["v4", "v5", "v6"],
  "versions": {
    "v6": {
      "label": "v6 · 邪恶版 · 世界之旅",
      "cards": [
        {
          "deck": "chance",
          "face": "smile",
          "event": "你在瑞士的匿名账户被发现……",
          "effect": "+2000，被举报者（最有钱的玩家）-2000"
        },
        {
          "deck": "fate",
          "event": "你在德州跟亡命牛仔玩「灵魂赌局」……",
          "cond": "押大小（前八步/后八步）",
          "win": "抢先开枪：+3000",
          "lose": "送进监狱 3 回合",
          "rate": "50%"
        }
      ]
    }
  }
}
```

对应关系：`version` 列的每个值 → `versions` 下的一个键；该版本的每一行 → `cards` 数组里一个对象；`seq`、`use` 两列不进 JSON。

## 五、填写规范

- **编码必须是 UTF-8 带 BOM**。Excel 另存为时选「CSV UTF-8（逗号分隔）」；Numbers 导出的 CSV 默认就是 UTF-8。编码错了中文会乱码。
- 单元格里可以正常写逗号、`"`、换行，Excel 保存时会自动加引号转义，脚本能正确读回。
- 表头一行不能动，列名必须完全一致。
- **行顺序 = 打印顺序**，同一 `version` 内先写满机会牌再写命运牌（页面按花色分组编号）。

## 六、脚本会拦什么（校验规则）

`tools/update.py` 跑一次全量校验，**任何一条不过就不写文件**，并在终端指出是哪一行：

| 检查 | 说明 |
|---|---|
| `version` 非空 | 缺了不知道归到哪个版本 |
| `deck` 只能是 `chance` / `fate` | 决定配色 |
| `event` 非空 | 卡面不能没字 |
| 机会牌 `face` ∈ `smile` / `frown` | 决定表情 |
| 机会牌 `effect` 非空 | 没有效果就不是机会牌 |
| 命运牌 `cond` / `win` / `lose` 非空 | 三件套缺一不可 |

另外终端会打印每个版本的机会/命运张数，方便一眼看出是不是填漏了。

> 校验只管结构和必填，**不管平衡性**。改了金额想验证零期望，得自己按「赢面 × 赢额 = 输面 × 输额」核对。
