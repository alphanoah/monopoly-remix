卡牌字段说明（`source/remix/cards.md`）

卡牌真源 cards.md 的字段怎么填、对应 JSON 字段、脚本校验规则、Excel 批量编辑与回导

30 秒速查：CSV / Excel 的 11 列

首页「机会/命运卡牌」区导出的 CSV / Excel，表头固定 11 列，与 cards.md 表格的对应关系：

CSV 列对应 md 列说明
version## 版本号属哪个版本，如 v7；回导时版本名沿用 cards.md 的 ## 标题
deck### 花色chance = 机会牌 / fate = 命运牌
seq编号只是人工核对号；页面卡号 n-20 按行序自动生成
face表情机会牌填 smile / frown，命运牌留空
event事件必填，卡面第一行
effect效果机会牌必填，命运牌留空
cond判定命运牌必填，机会牌留空（填了会被画成命运牌）
win赢命运牌必填，机会牌留空
lose输命运牌必填，机会牌留空
rate命中率纯备注，页面不读
use启用1 采用 / 0 弃用，留空当 1

最容易踩的坑：

  • 机会 / 命运要填的列互斥：页面靠 cond 有没有内容判断画哪种卡面，机会牌填了判定 / 赢 / 输会被当成命运牌画出来。
  • 保存选 CSV UTF-8，否则中文回导会乱码。
  • 别改列名：回导按列名读，缺列直接报错退出。
  • 导出含全部版本、连 use=0 的弃用牌一起：在 Excel 里整行删除就是删牌；想临时下架某张牌，把 use 改成 0 更安全，随时能加回来。
  • +3000 的正号丢了没关系：脚本读取时自动补回（effect / win / lose）。
  • 调卡牌顺序直接拖行：卡牌顺序 = CSV 行序；seq 不同步刷新不影响页面。

一、cards.md 的结构

三层结构：版本 → 花色 → 表格。

`markdown

v7 · 邪恶版 · 世界之旅（修订） ← 版本小节：首个词是版本号，整行是页面版本下拉里显示的名字

机会牌（20 张） ← 花色小节：以「机会」或「命运」开头

编号表情事件效果命中率启用
1smile你买的国足赢了世界杯+30001

命运牌（20 张）

编号事件判定赢输命中率启用
1你在美国跟牛仔决斗……押大小：……押中：+3000押错：送进监狱50%1

`

  • 加新版本：复制一个 ## 版本块改版本号即可；## 标题整行就是下拉里显示的名字。
  • 默认版本写死在 tools/lib/cards.py 的 DEFAULT_VERSION（当前 v7，该版本不存在时退到最后一个版本）——想让新版本当默认，改那一行；每版张数统计才是脚本现算的。
  • 空单元格 = 该字段留空（不进 JSON）；单元格里的竖线要转义成 \|。
  • 同一版本内两种花色的先后不影响解析（回导脚本固定先写机会牌）；表格行序 = 页面卡号顺序，CSV 里拖行就能调顺序。

二、字段对照

md 列JSON 字段类型 / 取值必填卡面显示在哪
（## 版本号）versions 的键如 v7✅决定版本下拉
（### 花色）deck机会 = chance / 命运 = fate✅决定底色与标题（机会=粉紫 / 命运=米黄）
编号❌ 不进 JSON整数，从 1 开始建议填不显示，仅作人工核对
表情facesmile 或 frown机会牌 ✅ / 命运牌留空机会牌的表情图标
事件event任意文本✅卡面正文第一行
效果effect任意文本机会牌 ✅ / 命运牌留空机会牌第二行
判定cond任意文本命运牌 ✅ / 机会牌留空命运牌「摇骰 · xxx」行
赢win任意文本命运牌 ✅ / 机会牌留空命运牌「赢：xxx」（笑脸）
输lose任意文本命运牌 ✅ / 机会牌留空命运牌「输：xxx」（哭脸）
命中率rate如 50%❌不显示，纯备注
启用❌ 不进 JSON1 采用 / 0 弃用❌（留空 = 1）0 的牌不出现
空值不进 JSON：转换时值为空的字段会被省略，JSON 里不会出现空字符串字段。

两种牌要填的列是互斥的：页面靠 cond 有没有内容区分渲染哪种卡面，
机会牌一旦填了「判定」，页面会把它当成命运牌来画（出现摇骰/赢/输三行），属于填错。

  • 表情：smile → 笑脸（奖励）/ frown → 哭脸（惩罚）；命运牌留空（表情由赢/输行固定）。
  • 命运牌三件套渲染成：摇骰 · <判定> / 😊 赢：<赢> / 😢 输：<输>。
  • 编号只用于人工核对；页面卡号 n-20 按表格行序自动生成，别让编号和行序对不上。
  • 命中率会原样进 JSON，但页面不读，纯粹方便核对零期望。
  • 想临时拿掉某张牌试效果，把「启用」改成 0 比删行安全，随时能加回来。

金额的正号不用操心

「效果 / 赢 / 输」里写 +3000 还是 3000 都行，显示出来都是 +3000：
只要一个格子整个就是一个正整数，脚本读取时自动补 +（负号和带文字的不受影响）。
这是为了兼容 Excel / Numbers —— 它们把 +3000 当数值，保存时正号会丢。

三、Excel 批量编辑工作流

  1. 首页「机会/命运卡牌」区点「导出 CSV」（或「导出 Excel」）。
  2. 用 Excel / Numbers 改。保存 / 导出时选「CSV UTF-8」，否则中文会乱码。
  3. 回导：python3 tools/import-cards.py 路径/文件.csv（加 -n 只校验不写）。
  4. 回导成功后再跑 python3 tools/build.py 同步页面。

CSV 中转格式的表头固定 11 列，与 md 字段一一对应：

`
version,deck,seq,face,event,effect,cond,win,lose,rate,use
`

  • 版本名（## 标题）不进 CSV；回导时沿用现有 cards.md 的版本名，新版本默认显示版本号大写，之后去 md 里改标题即可。
  • 回导脚本会复用构建脚本的同一套校验，并且把生成的 md 再解析一遍逐字段比对，不一致就不写文件。

四、脚本会拦什么（校验规则）

tools/build.py 跑一次全量校验，任何一条不过就不写文件，并在终端指出是哪张牌：

检查说明
版本 / 花色小节结构## 版本 → ### 机会或命运 → 表格，缺一不可
表头与列数列名、列序必须和约定完全一致（防止列错位）
event 非空卡面不能没字
机会牌表情 ∈ smile / frown决定表情
机会牌效果非空没有效果就不是机会牌
命运牌判定 / 赢 / 输非空三件套缺一不可

另外终端会打印每个版本的机会/命运张数，方便一眼看出是不是填漏了。

校验只管结构和必填，不管平衡性。改了金额想验证零期望，得自己按「赢面 × 赢额 = 输面 × 输额」核对。
